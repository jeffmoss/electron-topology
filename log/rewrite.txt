│                                                                                                   │
│ Key Observation                                                                                   │
│                                                                                                   │
│ All 3 existing kernels (geodesic_scan, berger_scan, lens_scan) have the identical function        │
│ signature:                                                                                        │
│                                                                                                   │
│ (num_param, param_min, param_step, p1_vals, q1_vals, p2_vals, q2_vals, num_pairs, block_results)  │
│                                                                                                   │
│                                                                                                   │
│ The only difference is what happens inside each thread (different path-length computation). This  │
│ means we can:                                                                                     │
│                                                                                                   │
│ 1. Keep separate .cu kernel files (each topology has its own physics) — no unified CUDA kernel    │
│ needed                                                                                            │
│ 2. Write one generic Rust scan function that takes a compiled kernel function + parameter bands,  │
│ eliminating the 3x duplication in main.rs                                                         │

│ Why Separate Kernels (Not One Unified Kernel)                                                     │
│                                                                                                   │
│ A single kernel with if (topology == TORUS) ... else if ... would cause warp divergence — all     │
│ threads in a warp must execute the same branch. Since all threads in a launch process the same    │
│ topology, separate kernels have zero overhead and maximum occupancy. The Rust-side generic        │
│ function handles the dispatch.                                                                    │

│ Step 2: Mode-Pair Generation Per Topology                                                         │
│                                                                                                   │
│ For S³ quotient topologies (Poincaré, dihedral, tetrahedral, octahedral), modes are Berger sphere │
│  modes filtered by a group-theoretic selection rule. The key function:                            │
│                                                                                                   │
│ // In physics.rs                                                                                  │
│ fn poincare_allowed_modes(max_j: i32) -> Vec<(i32, i32)>  // (j, m) pairs                         │
│ fn dihedral_allowed_modes(n: i32, max_j: i32) -> Vec<(i32, i32)>                                  │
│ fn tetrahedral_allowed_modes(max_j: i32) -> Vec<(i32, i32)>                                       │
│ fn octahedral_allowed_modes(max_j: i32) -> Vec<(i32, i32)>                                        │
│                                                                                                   │
│ For the GPU kernel, these filtered mode pairs get uploaded just like the existing winding-pair    │
│ arrays. The kernel itself is identical to berger_scan — the selection rule filtering happens on   │
│ the CPU side.                                                                                     │
│                                                                                                   │
│ For Nil manifold, mode pairs are (ℓ, j, m) triplets with abelian eigenvalues:                     │
│                                                                                                   │
│ λ_{ℓ,j,m}(τ) = (2πℓτ)² + (4π|ℓ|τ)(j + 1/2) + (2πm)²                                               │
│                                                                                                   │
│                                                                                                   │
│ The ratio is closed-form (like lens space), so no quadrature needed.                              │
│                                                                                                   │
│ Step 3: New GPU Kernels                                                                           │
│                                                                                                   │
│ kernels/poincare_scan.cu — Identical structure to berger_sphere.cu. Since mode pairs are          │
│ pre-filtered on CPU, the kernel just computes Berger path lengths for the given pairs. Can        │
│ literally reuse compute_berger_path_length by including common.cuh plus the berger_integrand      │
│ device function (either copy it or put it in common.cuh).                                         │
│                                                                                                   │
│ Actually, the simplest approach: move berger_integrand and compute_berger_path_length into        │
│ common.cuh so both berger_sphere.cu and poincare_scan.cu can use them. This is a small addition   │
│ to common.cuh.                                                                                    │
│                                                                                                   │
│ kernels/nil_scan.cu — Closed-form arithmetic kernel, similar to lens_space.cu:                    │
│ // Nil abelian eigenvalue ratio                                                                   │
│ double e1 = (2*PI*l1*tau)*(2*PI*l1*tau) + ...;                                                    │
│ double e2 = (2*PI*l2*tau)*(2*PI*l2*tau) + ...;                                                    │
│ ratio = e1 / e2;                                                                                  │
│                                                                                                   │
│ Step 4: Spectral Solvers                                                                          │
│                                                                                                   │
│ Poincaré homology sphere S³/2I:                                                                   │
│ - Selection rule: j must be even (j=2l), and l must be expressible as 6a+10b or 15+6a+10b for     │
│ non-negative integers a,b                                                                         │
│ - Surviving j values ≤ 60: {0, 12, 20, 24, 30, 32, 36, 40, 42, 44, 48, 50, 52, 54, 56, 60}        │
│ - Eigenvalue: same as Berger E(j,m) = j(j+2) + m²(1/λ²-1), but only for allowed j                 │
│ - Direct solve: same algebraic equation as Berger, but restricted to allowed (j,m) pairs          │
│                                                                                                   │
│ Nil manifold:                                                                                     │
│ - Abelian eigenvalues: λ_{m,n}(τ) = (2πmτ)² + (2πn)²                                              │
│ - Same structure as flat torus! Direct solve: τ² = (m₁²−T·m₂²)/(T·n₂²−n₁²)                        │
│ - Non-abelian (Landau levels): more complex, GPU scan better                                      │
│                                                                                                   │
│ Binary polyhedral groups (2D_n, 2T, 2O):                                                          │
│ - All use the same Berger eigenvalue formula                                                      │
│ - Different selection rules on (j,m):                                                             │
│   - 2D_n: j even, m ≡ 0 mod n                                                                     │
│   - 2T: j ∈ {0,6,8,12,14,18,...} specific pattern from representation theory                      │
│   - 2O: j ∈ {0,8,12,16,18,20,...} specific pattern                                                │
